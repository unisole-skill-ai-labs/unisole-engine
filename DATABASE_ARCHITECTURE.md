# Unisole Database Architecture & Schema Standard

This document serves as the **official specification and standard operating procedure (SOP)** for database schema definitions, migrations, and seeding across the Unisole Engine ecosystem.

---

## 1. The Single Source of Truth

To prevent schema drift, race conditions, and corrupted environments, the database follows a strict **single source of truth** architecture:

```
                  ┌─────────────────────────────────────────┐
                  │          src/db/schema.ts               │
                  │   ⭐ Single Source of Truth (Drizzle)   │
                  └────────────────────┬────────────────────┘
                                       │
                         npx drizzle-kit generate
                                       │
                                       ▼
                  ┌─────────────────────────────────────────┐
                  │             drizzle/*.sql               │
                  │     Version-Controlled Migrations       │
                  └────────────────────┬────────────────────┘
                                       │
                            npm run db:migrate
                                       │
                                       ▼
                  ┌─────────────────────────────────────────┐
                  │          PostgreSQL Database            │
                  │  (Local :5432 | Staging :5434 | Prod)   │
                  └────────────────────┬────────────────────┘
                                       │
                          npm run db:seed:system
                                       │
                                       ▼
                  ┌─────────────────────────────────────────┐
                  │    Canonical Foundational Data Sync     │
                  │ (Super Admin, GDC Theog, Flagship Decks)│
                  └─────────────────────────────────────────┘
```

### Roles & Responsibilities

| Component | Path | Purpose |
| :--- | :--- | :--- |
| **Canonical Schema** | [`src/db/schema.ts`](file:///c:/code/unisole/unisole-engine/src/db/schema.ts) | Defines all tables, columns, constraints, foreign keys, enums, sequences, and TypeScript types. |
| **Entity Relations** | [`src/db/relations.ts`](file:///c:/code/unisole/unisole-engine/src/db/relations.ts) | Defines relational mappings for nested Drizzle queries. |
| **Migration Files** | [`drizzle/*.sql`](file:///c:/code/unisole/unisole-engine/drizzle) | Immutable, incremental SQL scripts generated by Drizzle Kit. |
| **Migration Runner** | [`src/scripts/migrate.ts`](file:///c:/code/unisole/unisole-engine/src/scripts/migrate.ts) | Executes pending migrations against PostgreSQL. |
| **System Seeder** | [`src/scripts/seed-system.ts`](file:///c:/code/unisole/unisole-engine/src/scripts/seed-system.ts) | Idempotent seeder for foundational data (Super Admin, official college branches, presentation decks). |
| **Demo Seeder** | [`src/scripts/seed-demo-analytics.ts`](file:///c:/code/unisole/unisole-engine/src/scripts/seed-demo-analytics.ts) | Mock/demo data generator guarded with safety checks against production execution. |

## 2. Legacy Cleanup Record

The following redundant/legacy artifacts have been **completely eliminated**:

1. ❌ **`edtech_schema_and_seed.sql` (Deleted)**
   - *Issue:* 1,500+ line legacy raw SQL dump. Lacked modern enums (`SUPER_ADMIN`, `MEMBER`), missing entire modules (presentations, tasks), and caused collisions on fresh Docker runs.
   - *Resolution:* Removed from the repository and unmounted from all Docker Compose configurations.

2. ❌ **`src/db/init.ts` (Deleted)**
   - *Issue:* 863 lines of raw imperative SQL (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ADD COLUMN`) executed on every server restart.
   - *Resolution:* Completely removed. Server startup in `src/index.ts` now only performs a non-destructive health ping (`SELECT 1`).

3. ❌ **`POST /api/public/sync-db` (Removed)**
   - *Issue:* Unauthenticated public endpoint executing arbitrary raw schema alterations.
   - *Resolution:* Endpoint removed from `src/routes/public/index.ts`.

## 3. Standard Operating Procedures (SOP)

### How to Modify the Database Schema

#### Step 1: Update TypeScript Schema
Edit [`src/db/schema.ts`](file:///c:/code/unisole/unisole-engine/src/db/schema.ts) to declare your new table, column, index, or enum:
```typescript
export const users = pgTable("users", {
  id: varchar("id", { length: 50 }).primaryKey().default(sql`('usr_' || nextval('users_id_seq'::regclass))`),
  username: varchar("username", { length: 100 }),
  // ...
});
```

#### Step 2: Generate Migration SQL
Run Drizzle Kit to automatically detect differences and create the migration file:
```bash
npm run db:generate
```
This generates a new timestamped migration inside the `drizzle/` directory (e.g. `drizzle/0003_xxx.sql`).

#### Step 3: Run Migrations
- **In Local Development:**
  ```bash
  npm run db:migrate:dev
  ```
- **In Staging / Production (Docker / CI/CD):**
  ```bash
  npm run db:migrate
  ```

#### Step 4: Seed Foundational Data (If Applicable)
```bash
npm run db:seed:system
```

## 4. Schema Overview & Domain Modules

### 1. Identity & Access Management (IAM)
- **`users`**: Platform users (students, team members, admins, super admins).
- **`user_role`**: Enum (`STUDENT`, `MEMBER`, `ADMIN`, `SUPER_ADMIN`).
- **`otp_verifications`**: Mobile phone OTP authentication & rate limiting.

### 2. Institutions & Academic Structure
- **`colleges`**: Partner universities and institutions (e.g. Government Degree College Theog).
- **`branches`**: Academic departments/branches (e.g. `BCA`, `BBA`, `BCOM`, `BA`, `BSC_NM`, `BSC_MED`).

### 3. Curriculum & Learning (LMS)
- **`categories`**: Pathway subject groupings (AI, Data, Web, etc.).
- **`pathways`**: Career pathways with roadmap stages.
- **`courses`**, **`modules`**, **`lessons`**: Hierarchical course content.
- **`enrollments`**: Student course/pathway enrollments.
- **`payments`**: Transaction records, Razorpay order/payment tracking.

### 4. Interactive Presentations & Roadshows
- **`presentations`**: Slide decks (e.g. Theog College Career Awareness Deck, AI Campus Deck).
- **`presentation_sessions`**: Live audience session codes and real-time state.
- **`presentation_leads`**: Student lead captures, stream interest, and contact info.
- **`session_responses`**: Interactive poll responses submitted by students during live roadshows.

### 5. Task & Team Operations
- **`team_departments`**: Functional units (Engineering, Marketing, Curriculum).
- **`team_members`**: Organization staff profiles.
- **`tasks`** & **`task_activities`**: Internal sprint task management and review workflows.
